# 閲覧用サイト (`req site`) の設計

README の[可視化](../../README.md#可視化)が「何ができるか」を書くのに対し、
ここは**なぜその作りなのか**を残す。画面の挙動を変えるときに読む文書。

## 描画エンジンの選定とレイアウト方針

描画は **ブラウザ標準の SVG DOM**、レイアウトは **dagre** (バージョン固定の UMD ビルド) を使う。
グラフはページ読み込み時に 1 度だけレイアウトし、その後の操作は
**要素の見せ消しとクラスの付け替えだけ**で行う。

- 絞り込みのチェックを 1 つ変えても再レイアウトは走らず、**ノードの位置が動かない**。
  読み手が覚えた「あのノードはこの辺」が壊れない
- 影響範囲のハイライトも同様。ノード選択で図全体が描き直されることはない
- パン・ズームは SVG の `transform` を表示層で更新する。ドラッグ後にブラウザが発火する
  `click` はパンとして消費し、選択中ノードを解除しない

dagre にはノード寸法と表示中のエッジを渡し、**ノード座標だけ**を受け取る。
その後で帯を適用して最終座標を決め、エッジは最終的な 2 ノード間を短い二次 Bézier
として `<path>` で描く。先頭・末尾は実際のノード形状の境界へ切り詰める。
同じランクのノード間だけは距離に応じて帯の外側へ 8〜48px 膨らませ、同じ 2 ノード間の複数エッジと
逆向きエッジは制御点を 12px ずつずらして、ラベルと線を判別できるようにする。

dagre の `points` を採用しないのは、その経路が帯を適用する**前**のノード座標を前提に
しているためである。帯の再配置後まで中間点を残すと、端点から遠く離れた迂回や尖りが
発生する。最終座標から引き直すことで、経路の短さと表示の一貫性を優先する。

絞り込みで消えたノードの場所は空いたままになる。詰め直したいときはツールバーの
**「整列」** を押すと、表示中のノードだけで並べ直す。TD / LR の切り替えも並べ直す。

初期表示はグラフ全体を収める倍率にするが、極端に横長のグラフで文字が潰れないよう
下限 (0.45 倍) を設けてあり、そこから先は左上を起点にパンして見る。
**下限に張り付くほど大きいモデルでは、全体を 1 枚に収めること自体を諦めてフォーカスを使う** (下記)。

大きいグラフでは選択したノードが表示範囲の外にあることが多いので、左サイドバーの
一覧や指摘から選んだノードが画面外なら、そのノードが見える位置まで短くパンする。
**倍率は変えず、既に見えているノードでは動かさない** (グラフ上のノードを直接
クリックしたときは当然見えているので、ビューは動かない)。

既定では CDN を参照する。`--assets local` を渡し、出力先に
`dagre.min.js` を置けば、外部への通信が一切無い
自己完結のサイトになる (Pages のワークフローはこの方式で公開する)。
同梱するのはこの 1 ファイルだけでよい。URL とファイル名は
`reqmodel.presentation.site.SITE_ASSETS` を唯一の出典とする。

### SVG DOM 置換時の実測 (#94)

2026-08-05、Chromium・1440×1000・CDN キャッシュ済みで生成サイト自身が記録した値。
時刻は `Date.now()` のため 1 ms 単位で、ネットワーク時間を含まない。

| モデル / 操作 | ノード | 時間 |
|---|---:|---:|
| sample 初期描画 | 21 (既定表示 14) | 37 ms |
| sample 絞り込み | 14 → 13 | 0–1 ms |
| sample フォーカス 2 ホップ | 6 | 8 ms |
| sample TD → LR | 6 | 5 ms |
| bench 初期描画 | 300 (既定表示 294) | 347 ms |
| bench 全体レイアウト | 294 | 294 ms |
| bench 絞り込み | 294 → 約 163 | 1 ms |

sample / 約 163 ノード / 300 ノードで SVG・ノード・経路・帯の非ゼロ描画と
console / page error が無いことを実ブラウザで確認した。絞り込み前後の全可視ノードの
`transform` も比較し、残ったノードの座標が 1 件も変わらないことを確認した。

配布アセットは固定版 CDN ファイルの実サイズで、置換前の 2 ファイル
(`cytoscape.min.js` 435,328 bytes + `cytoscape-dagre.js` 56,856 bytes = 492,184 bytes)
から、`dagre.min.js` 1 ファイル (96,135 bytes) になった。ファイル数は 2 → 1、
合計は 396,049 bytes (約 80.5%) 減った。

## 大きいグラフでの表示戦略 (フォーカス)

**問題は倍率ではなく形にある**。要求グラフは 1 つの Need に FR がぶら下がる形なので、
FR が同じ段に何十件も並び、図は極端に横長になる。300 ノードのベンチ用モデル
(`examples/bench.py`) で測ると**アスペクト比は 26:1**、全体を収める倍率は下限
(0.45) に張り付き、その倍率ではノードの文字が読めない。これは
レイアウトエンジンの問題ではない (#23 で dagre と Graphviz が同じ形になることを確認した)。

採ったのは**フォーカス**である。ツールバーの選択で深さ (1〜3 ホップ) を選ぶと、
図に描くのは**選択ノードの近傍だけ**になり、その部分グラフだけで並べ直す。
探索はエッジの向きを無視する (`req explain --undirected` と同じ。上流の Goal 側と
下流の FR 側のどちらが欠けても文脈にならないため)。

| 表示 | 描かれるノード | 倍率 |
|---|---|---|
| 全体 (300 ノード) | 300 | 0.45 (下限に張り付き、文字が潰れる) |
| フォーカス 1 ホップ | 4 | 1.12 |
| フォーカス 2 ホップ (源泉あり) | 53 | 0.57 |
| フォーカス 2 ホップ (源泉なし = 既定) | 9 | 0.87 |
| フォーカス 3 ホップ (源泉なし = 既定) | 13 | 0.85 |

源泉を 1 つ経由するだけで近傍が一気に広がる (上の 53 件がそれ)。Source は数十件の
要求から参照されるハブだからで、この測定が
[Source を図に描かない](model.md#source-を図に描かない) 判断の根拠の 1 つになった。
いまは既定で外れているので、深さ 2〜3 でも表の下 2 行の側になる。
エッジ種別の絞り込みはフォーカスの探索にもそのまま効く。

要点は**フォーカスが図の描画にしか効かない**ことである。左の一覧・テーブル・詳細
ペインの上流/下流の件数・「影響部分グラフをコピー」の本文は、フォーカス中も
**全体のまま**変わらない。ここを近傍で切ると、コピーした内容が `req explain` と
別物になり、LLM に渡すコンテキストが黙って欠ける。

種別や status の絞り込みでは**位置を保つ**が、フォーカスは描く範囲そのものが
変わるので**並べ直す**。選択を変えるたびに近傍が並び直り、読める倍率に戻る。

図に描く範囲を絞るフォーカスは、左サイドバーの**影響範囲**の深さとは別物である。
影響範囲の深さは色分けとコピー本文に効き、フォーカスは描画にしか効かない。

### 見送った候補

| 候補 | 採否 | 理由 |
|---|---|---|
| 近傍だけを描く (フォーカス) | **採用** | 規模に依存しない。既存の絞り込み・パーマリンクとそのまま噛み合い、追加はロジック側の探索 1 つで済む |
| Goal / Need 単位のクラスタ表示 + クリックで展開 | 見送り | 粒度が Goal 木の形に依存し、FR が特定の Goal に偏る実モデルでは効きが読めない。帯はクリックを素通しする背面 SVG として描く |
| 同一ランクに並びすぎるノードを複数行に折る | **RequirementGroup 内だけ採用** | dagre の経路は使わず、グループ内では並び順だけを引き継いで表示上の行を折る。エッジの接続関係は変えない |
| 別レイアウト (`elk` 等) の採用 | 見送り | 横長さは要求グラフの構造そのものから来るので、レイアウトを替えても比は変わらない。配布物が増える割に問題が動かない |

## Goal / Need の帯表示

エッジの向きは混在している (`motivates` は Goal→Need と下向き、`satisfies` は
FR→Need と上向き) ため、レイアウトエンジンに任せるだけでは Goal と FR が同じ
高さに並んでしまう。最上位にあたる Goal と上位にあたる Need は型ごとの
**帯 (ラベル付きの枠)** にまとめ、**Goal → Need → その他** の順で常に図の上
(LR では左) に置く。

- 帯の中の Goal は `refines` の親子で行を分け、親を上に置く
- **枠は図の全幅に揃える**。等幅・同位置の枠が縦に並び、中身はその中央に寄る。
  帯ごとに中身の外接矩形を掛けると幅も左端もばらばらになり、層に見えないため
- 帯の中の左右の並びは dagre の結果を保つが、絶対座標と間隔は引き継がず、
  ノード幅と一定間隔だけで詰め直す。表示幅を超える Goal / Need は同じ階層のまま
  次行へ送り、不要な空白や長い一行を段幅へ波及させない
- 枠はクリックを素通しするただの背面描画で、選択・影響範囲・検索には関わらない
- 種別の絞り込みでその型を外せば、枠ごと消える
- Goal / Need の帯にする型とラベルは `presentation/styles.py` の `_BANDS` を唯一の出典とし、meta 経由で
  ページに渡る (帯の並べ直しそのものは `site_logic.js` の `bandedLayout()`)
- Requirements 段は `RequirementGroup` を出典にした表示専用の機能枠で横方向に並べる。
  これは presentation 層のビュー定義であり、FR / QR / Constraint の公開ノード型へ
  表示都合の `group` フィールドは足さない
- RequirementGroup 内の同じ `refines` 階層は dagre の順序だけを使って詰め、グループの
  最大幅で折り返す。グループ自体は折り返さず同じ段へ並べ、Goal / Need / Requirements
  の段幅を揃える。Requirements 段の表示幅は表示中グループへ均等に配分し、グループ数が
  多いときは各枠内の折り返しを増やして共通の段幅を必要以上に広げない。TD / LR は主軸と
  副軸を交換して同じ計算を使う
- 1 ノードの主所属は 1 つだけで、複数グループの `members` に現れた場合は
  `order` と `id` で最初に来るグループへ描く。未指定の FR / QR / Constraint は
  `未分類` 枠へ置き、枠をまたぐ関係は通常のエッジとして残す

## ノードラベルの収まりと折り返し

ラベル (id + 本文) は**図形の内側に収める**。ノードの外形をラベルの外接矩形に
合わせると、内側が矩形より狭い図形 (六角形・菱形・楕円) では文字が
図形の外に出るため、**形状ごとの係数で外形を決める**。

- 中央に置いたテキスト矩形の、外形に対する比を `a` (幅) `b` (高さ) とすると、
  収まる条件は形状ごとに `a <= f(b)` の形になる (六角形なら `a <= 1 - b/2`、
  菱形なら `a <= 1 - b`、楕円なら `a² + b² <= 1`)。この式から決めた倍率と余白が
  `presentation/styles.py` の `_SHAPE_FIT`。形状の定義と同じく **Python 側が唯一の出典**で、
  meta 経由でページに渡る
- ラベルの幅はブラウザで**実測する** (SVG と同じ字体で canvas に測らせる)。
  字体の定義は `site_logic.js` の `LABEL_FONT` が唯一の出典で、実測とスタイルの
  両方がそこを見る

折り返し (`wrapLabel()`) は文字数ではなく**実測幅**で折る。SVG の `<text>` は
自動折り返ししないので自前で折るが、単純に N 文字で
切ると「24 / 時間」のように数値と単位が分かれてしまう。

- まず文を**文節らしいまとまり**に切る。送り仮名・助詞は直前の語から離さず、
  数値は単位を連れていく (`24 時間`、`99.9% 以上`)
- そのまとまりを、幅に入るだけ 1 行に詰める。句読点や閉じ括弧は行頭に置かない
- **数字や記号だけの行は作らない**。1 つのまとまりが 1 行に入らないときだけ、
  最後の手段として幅で切る

完璧な日本語組版は狙わない。図の中で読めれば十分という水準に留めてある。

## 表現の割り当てと重ね順

ノードには型・status・影響範囲・検索ヒットという 4 つの軸が同時に載る。
**互いを潰さないように、奪い合わない表現に割り当ててある**。

| 軸 | 表現 |
|---|---|
| 型 | 形 + 塗り + 枠線の色 |
| status | 枠線の**線種** (verified は内側リングを加えた二重線) |
| 影響範囲 | 枠線の**色と太さ** (選択=赤 / 上流=青 / 下流=緑 / 関連=紫) |
| 検索ヒット | ノードの下に敷く**暈し** |

要点は status を**線種だけで**区別できるようにしてあることである。影響範囲の
ハイライトは枠線の色と太さを奪うため、太さに意味を持たせると強調中に status が
読めなくなる。線種は奪われないので、**影響範囲を追いながら同時に status も
読める**。verified の内側リングも強調用の外枠とは別要素なので残る。
検索が奪う表現も 1 つも無く、影響範囲の外にある
ヒット (減光中) も暈しが読める程度に残す。線種の太さは線種の補強でしかない。

画面の SVG/CSS は、基本 → 型 → status → 状態 (影響範囲・見せ消し) → 検索 (暈し) の順に
意味を分けており、この順序が「どの表現がどれを上書きするか」の決定そのものになっている。

輪 (`outline-*`) が空いているのは、優先度を落としたため
([メタモデルの判断](model.md#優先度を属性として持たない))。軸を足すなら、
どの property も奪っていないここが最初の置き場になる。

形状・ライト／ダーク別の配色・status の線種・影響範囲の色・検索ヒットの暈しの色は、`presentation/styles.py` の
`render_meta()` がまとめてページに渡す。描画の定義をブラウザ側に複製しないための
出口であり、見た目を変えるなら `presentation/styles.py` だけを触ればよい。凡例もこの meta から
組むので、定義を足せば凡例にも自動で並ぶ。ダークテーマでは明るい文字に合わせて
ノードの塗りを同じ色相の暗色へ切り替え、白に近いライト用の塗りを流用しない。

## 表示状態の実装 (URL と localStorage)

表示状態は URL のハッシュが唯一の出典で、操作するたびに書き戻される
(載る項目は README の[パーマリンク](../../README.md#url-に載る表示状態-パーマリンク)を参照)。

- **既定値は書かない**。初期表示のままなら URL にハッシュは付かず、載っている項目が
  そのまま「既定と違うところ」の一覧になる
- **戻る/進むで表示状態を辿れる**。選択・絞り込み・並べ替えは履歴に積み、検索語だけは
  1 打鍵ごとに履歴が増えないよう最後のエントリを置き換える
- 同じページを開いたままハッシュだけ変えても (`hashchange`) 表示は追従する
- URL は手で書き換えられる場所なので、**解釈できない値は黙って捨てる** (存在しないノード
  id、知らない種別、壊れたエスケープ)。読み込み後に URL は解釈できた形へ直される
- 検索候補を送っている最中の位置は URL に載せない。決めた選択 (`#node=...`) だけが表示状態である

`site_logic.js` の `encodeHash()` / `decodeHash()` が状態と `#...` の相互変換を持ち、
DOM も履歴も触らない純関数なので往復はテストで担保している。絞り込みの軸
(種別・エッジ種別・status) は `SET_FILTERS` の 1 行で対応付けてあり、
軸を足せば既定値・URL への書き出し・復元の 3 つが揃って増える。

**絞り込みと表示は `localStorage` にも残る**。パーマリンクは「いまの画面を人に渡す」
ためのもので、次に自分が開いたときには効かないためである。

- 保存するのは**絞り込みと表示だけ**。選択ノードと検索語は持ち越さない
  (前回見ていた 1 件が復活しても嬉しくない)
- **URL のハッシュが最優先**。ハッシュ付きの URL を渡された側で、その人の前回の
  絞り込みが混ざることはない
- 保存も復元も `#...` 1 本 (`storableHash()` / `initialHash()`) でやり取りするので、
  パーマリンクと同じ経路に乗る。`localStorage` が使えない環境では黙って諦める
- テーマの固定 (`<html data-theme="light|dark">`) も同じく `localStorage` に残り、
  自動に戻すと外れる。図の配色も同じ CSS 変数から引き直す

## 書き出した図が CLI と一致すること

**サイトが配るものは CLI の出力と一致していなければならない**。食い違うと、
気付かないまま別物を配ることになる。`tests/test_site_js.py` が
`examples/sample.py` で両者を突き合わせる。

| ページ | CLI | 突き合わせ |
|---|---|---|
| `nodeContext()` (「影響部分グラフをコピー」) | `explain_text()` | 全ノード。絞り込み中は `req explain --edges / --depth / --undirected` に対応 |
| `mermaidText()` (「.mmd」で書き出す図) | `render_mermaid()` | 絞り込み無しのとき一字一句同じ |

SVG の書き出しは、画面にある SVG DOM を複製し、非表示要素を除いてテーマ色を
埋め込んだ自己完結 SVG として直列化する。画面と書き出しで形状・経路を別々に組み立てない。

影響範囲についても、色分けもコピー本文も同じ `impactSets()` から範囲を貰うので、
「画面では 2 ホップに絞っているのにコピーは全体」が起きない。向きを無視したときは
`impact_set()` が全件を「関連」として返すのに合わせ、図でも 1 色 (紫) で塗る。

## ページの JS の構成とテスト

出力は 1 枚の HTML だが、**ソースはテンプレートから分けてある**。

| ファイル | 役割 |
|---|---|
| `site_logic.js` | ロジック層。DOM も描画 API も触らない純関数だけ |
| `site_app.js` | 表示層。DOM・SVG・dagre に触るのはここだけ |
| `site_template.html` | 骨組みと CSS。JS は `__APP_JS__` の 1 か所に入る |

`presentation/site.py` の `app_js()` が 2 つを連結して 1 つのモジュールにし、テンプレートへ
インライン化する。連結にあたって落とすのはファイル間の `import` / `export` 行だけで、
最小化もトランスパイルもしない。生成された HTML の中身は書いたままの JS である。

分ける目的は**テストできるようにすること**。`site_logic.js` は素の ES モジュールなので、
Node からそのまま読み込める。

```console
$ npm run lint    # node --check (依存パッケージは無い)
$ npm test        # node --test tests/js/*.test.mjs
```

## ベンチ用サンプル

`examples/bench.py` は 300 ノード / 611 エッジの合成モデルである
(FR 191 件。同じ段に並ぶ幅がそのまま図の横長さになる)。**生成物**であり、
`python tools/gen_bench.py` が書き出す。定義ファイルは宣言のみ (層0) なので、
生成器はモデルの外に置く。指摘が 0 件になるよう作ってあり
(`tests/test_bench_example.py` が生成器との一致と併せて見張る)、
ベンチの邪魔になる指摘は残らない。

```console
$ req site examples/bench.py -o bench-site && python -m http.server -d bench-site
$ npm run bench          # 探索まわりの時間 (tests/js/bench.mjs)
```

`reach()` は隣接マップを 1 度組んでから辿る。組む前は BFS の 1 ステップごとに
全エッジを走査していたため 1 回が O(V×E) で、300 ノードで **10 倍以上**、1200 ノード
(`node tests/js/bench.mjs 4`) では **60 倍以上**の差になる。フォーカスは選択のたびに探索を呼ぶので、
ここが線形であることが前提になる。
